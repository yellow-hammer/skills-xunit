# xUnit (Vanessa-ADD)

Тест 1С для Vanessa-ADD - это внешняя обработка, не файл `.os`. Исходники лежат в `tests/epf/<Имя>/` (выгрузка конфигуратора или проект EDT). Перед прогоном обработка собирается в `.epf`.

Файл `.os` с `&Тест` - это OneScript (OneUnit или 1testrunner), к xUnit он не относится.

## Модуль объекта

```bsl
Перем КонтекстЯдра;
Перем Утверждения;

Процедура Инициализация(КонтекстЯдраПараметр) Экспорт
	КонтекстЯдра = КонтекстЯдраПараметр;
	Утверждения = КонтекстЯдра.Плагин("БазовыеУтверждения");
КонецПроцедуры

Процедура ЗаполнитьНаборТестов(НаборТестов, КонтекстЯдраПараметр) Экспорт
	КонтекстЯдра = КонтекстЯдраПараметр;
	НаборТестов.Добавить("ПроверитьСложениеЧисел");
КонецПроцедуры

Процедура ПроверитьСложениеЧисел() Экспорт
	Утверждения.ПроверитьРавенство(2 + 2, 4, "Сложение целых чисел");
КонецПроцедуры
```

Загрузчик сначала вызывает `ЗаполнитьНаборТестов` с двумя аргументами и, если параметров слишком много, повторяет вызов с одним `НаборТестов`. Оба вида встречаются в чужих обработках. `ПолучитьСписокТестов` - запасной путь, если первого метода нет. У текущего загрузчика эта функция без параметров. Сигнатура с аргументом `ЮнитТестирование` отвергается. Имя в наборе совпадает с экспортной процедурой. Префикс `Тест` или `ТестДолжен_` не нужен: раннер вызывает имя как есть. В дымовых обработках add встречаются и `Fact_`, и `Тест_`, и `ТестДолжен_`.

`ПолучитьСписокТестов(КонтекстФреймворкаBDD)` в `step_definitions` - это шаги Vanessa, не тест xUnit.

Плагин `БазовыеУтверждения` сравнивает два значения: `ПроверитьРавенство(Первое, Второе, Пояснение)`. В примере первым идёт выражение, вторым эталон. Того же плагина хватает для `ПроверитьИстину`, `ПроверитьЛожь`, `ПроверитьЗаполненность`, `ПроверитьТип`, `ПроверитьВхождение`. Если в модуле уже `УтвержденияBDD` и `Ожидаем.Что`, не переписывай проверки на `ПроверитьРавенство`.

Дымовые обработки поставляются пакетом `add` в `oscript_modules/add/tests/smoke`. Не копируй их каркас в свой модуль.

## Настройки и запуск

Путь к собранным `.epf` передаётся аргументом: `vrunner test xunit <путь>` (в настройках runner это `testsPath`). `tools/xUnitParams.json` через `--xddConfig` задаёт настройки прогона, не каталог своих тестов. Ключей, которых в файле нет, не добавляй.

Дымовой прогон пакета `add` - другой набор: `$addRoot/tests/smoke`, ключи `smoke`, `CommandInterface`, `SmokeCommonModules`. Это не образец своего модуля и не путь к своим обработкам.

Для runner 3 отчёт задавай `--report-format junit --report-path`. Строка `jUnit{каталог};allure{каталог}` - устаревший `--reportsxunit`, в 3.0 он ещё работает. В runner 2 те же пути пишут генераторами `ГенераторОтчетаJUnitXML` и `ГенераторОтчетаAllureXMLВерсия2`. Код возврата `vrunner` по результату тестов есть только если задан `--xddExitCodePath`.

vanessa-runner 3: `vrunner test xunit`. vanessa-runner 2: `vrunner xunit`. Опции в 3.x стоят перед путём обработки. Запускается обработка целиком, не один метод.

Прогоны по одной базе идут по очереди. Незакрытое окно 1С - зависший сеанс. Второй прогон в ту же базу при живом клиенте не запускай.
